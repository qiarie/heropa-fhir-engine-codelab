9. Save the registered patient

In this step, you'll turn the answers into a FHIR Patient and save it in the local database. Turning answers into FHIR resources is called data extraction. The questionnaire contains a Patient template, and the TemplateExtractionEngine class of Kotlin FHIR Data Capture fills it in with the answers.

Open PatientListViewModel.kt. Make the two changes below in order.

Replace line 36 with the following code.

// 9 Imports for saving the patient
import dev.ohs.fhir.datacapture.extraction.template.TemplateExtractionEngine
import dev.ohs.fhir.model.r4.Questionnaire
import kotlinx.serialization.json.Json

Copy the second line exactly. This file needs the FHIR resource named Questionnaire, not the form you imported in step 8.

In registerPatient(), find the // 9 Replace with code from the codelab to extract and save the patient. comment and replace it with the following code:

// 9 Extract and save the patient
val questionnaire = Json.decodeFromString<Questionnaire>(questionnaireJson)
val bundle = TemplateExtractionEngine.extract(questionnaire, questionnaireResponse)
val extracted = bundle.entry.firstNotNullOf { it.resource as? Patient }
val patientId = fhirEngine.create(extracted).first()
val patient = extracted.copy(id = patientId)

The comment is on line 155 now that the imports are in. Press Ctrl+F and type // 9 Replace to jump to it, and replace that one line with the block above. Leave the // 11 comment under it for step 11. Save the file.

  • Json.decodeFromString() turns the questionnaire JSON into a Kotlin FHIR Questionnaire.
  • TemplateExtractionEngine.extract() returns a transaction Bundle with the extracted resources. For this questionnaire, the Bundle holds one Patient.
  • fhirEngine.create() saves the patient in the local database. The extracted patient has no ID, so the engine creates one and returns it. You'll use the patient with its ID in step 11.

The starter already runs registerPatient() in a coroutine. If the code fails, it shows the error as a message. When the code finishes, it reloads the patient list.

Now run it. Wait for BUILD OK in the Build log, then go to the App preview tab.

Run the app and register a patient. The new patient appears in the list, unless the search field filters it out. Tap Sync to upload it, then open your lab address followed by /fhir/Patient in a browser to see it on the FHIR server.
