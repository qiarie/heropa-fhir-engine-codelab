11. Propose tasks with the PlanDefinition

In this step, you'll apply the PlanDefinition to each new patient, and save the Tasks it proposes.

Open PatientListViewModel.kt. Make the two changes below in order.

Replace line 40 with the following code.

// 11 Imports for proposing tasks
import dev.ohs.fhir.model.r4.Date
import dev.ohs.fhir.model.r4.FhirDate
import dev.ohs.fhir.workflow.FhirOperator
import kotlin.time.Clock
import kotlinx.datetime.TimeZone
import kotlinx.datetime.todayIn

In registerPatient() in PatientListViewModel.kt, find the // 11 Replace with code from the codelab to propose tasks for the patient. comment and replace it with the following code:

// 11 Propose tasks for the patient
val today = Clock.System.todayIn(TimeZone.currentSystemDefault())
val carePlan =
  FhirOperator(EngineWorkflowRepository(fhirEngine))
    .generateCarePlan(
      planDefinitionCanonical = REGISTRATION_PLAN,
      subject = patient,
      variables = mapOf("today" to Date(value = FhirDate.fromString(today.toString()))),
      today = today,
    )
val tasks =
  carePlan.contained.filterIsInstance<Task>().map { it.copy(id = null, basedOn = emptyList()) }
fhirEngine.create(*tasks.toTypedArray())

The comment is on line 168 now that the imports are in, just under the code from step 9. Press Ctrl+F and type // 11 Replace to jump to it, and replace that one line with the block above. Save the file.

  • FhirOperator is the entry point of the workflow library. It finds the PlanDefinition by its canonical URL, REGISTRATION_PLAN, which is already in the starter.
  • generateCarePlan() runs PlanDefinition/$apply for the patient. It checks the condition of each action, and creates a Task with the intent proposal for each action that applies. It returns the Tasks inside a CarePlan, in contained.
  • variables makes %today available to the conditions. generateCarePlan() also takes today, but this version of the library doesn't pass it to the conditions, so the code passes today's date both ways.
  • The Tasks come with IDs from the PlanDefinition actions, which would be the same for every patient. Setting id to null lets the engine create a new ID for each Task. basedOn points into the CarePlan, which the app doesn't save, so the code removes it.
  • fhirEngine.create() saves the Tasks in the local database.

Now run it. Wait for BUILD OK in the Build log, then go to the App preview tab.

Run the app and tap Sync, so that the PlanDefinition is on the device. Then register a child born less than 5 years ago, and an adult. Type the date in the format shown in the field, for example dd/mm/yyyy. Each new patient shows its Tasks in the list. The child gets First visit and Child health check, and the adult gets only First visit.
